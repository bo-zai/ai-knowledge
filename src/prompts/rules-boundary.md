# 边界知识提取规则

## 定义
边界知识记录已有能力的局限性和被禁用的功能。

## 提取重点
1. **局限性**：能力目录中某个能力的范围限制（如只支持某些渠道、不支持某些场景）
2. **禁用功能**：代码中存在实现但配置关闭的功能（如开关设为 false 的功能）

## 多条提取要求
- 从 evidence 中仔细分析，提取**多条**边界知识
- 每个独立的局限性或禁用功能单独成条
- 不要把多个边界合并为一条

## 过滤规则
- 不从能力目录中简单取反生成缺失清单
- 禁用功能判断必须来自配置文件的显式值（如 switch=false）
- 只记录有明确代码证据的边界

## 生成约束
- **详细说明要简洁**：直接陈述事实，不包含任何解释、推理过程或"这意味着"等表述
- 每条边界知识必须说明对 Agent 后续工作的影响
- 局限性描述必须基于已有代码的总结，不推断缺失功能
- 别名必须包含英文标识符（如 PaymentChannelLimit）

## 详细说明示例
反面（包含解释）：
"在项目配置中只发现了微信支付配置文件，未发现支付宝配置。这意味着应用仅支持微信支付一种渠道，不支持其他支付方式。"

正面（简洁事实）：
"项目只配置了微信支付（wxpay.properties），未发现支付宝、银联配置文件。"
