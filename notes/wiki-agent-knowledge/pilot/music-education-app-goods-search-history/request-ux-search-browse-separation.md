# 需求样例 B：区分主动搜索与普通浏览

## 业务背景

客服和运营反馈，有些用户在商城里输入过关键词后，再去切换分类或返回列表继续浏览，会觉得结果“不对劲”，因为页面看起来像在浏览商品，但实际结果又像被之前的输入内容限制过。这个问题会让用户误以为商品不全，影响继续浏览和下单。

## 需求目标

让商城商品列表在“主动搜索”和“普通浏览”两种场景下表现更一致、更容易理解，减少用户因为结果范围不清楚而产生的困惑。

## 用户场景

### 场景 1

用户在商城搜索框里输入“古筝教材”并主动搜索，希望列表只展示与这次搜索意图相关的商品。

### 场景 2

用户搜索完成后，再切换到其他分类继续浏览，希望分类浏览看到的是该分类下的商品，而不是继续被上一次搜索条件影响。

### 场景 3

用户清空搜索框后继续浏览商品，希望页面恢复到正常浏览状态，而不是继续展示上一轮搜索结果。

## 需求范围

- 仅涉及商城商品列表页的搜索与浏览切换体验
- 不涉及首页搜索框视觉改版
- 不涉及新增推荐算法

## 需求说明

1. 用户主动发起搜索时，列表应按这次搜索意图返回结果。
2. 用户切换为普通浏览后，列表不应继续受上一次搜索条件影响。
3. 用户清空搜索内容后，应回到正常浏览商品的状态。
4. 本次改动不能影响商品详情、推荐商品、短信验证码和兑换流程。

## 验收标准

1. 主动搜索某个关键词时，返回结果应与用户输入意图一致。
2. 切换分类后，分类浏览结果不应被上一轮搜索残留条件干扰。
3. 清空搜索内容后，商品列表能恢复正常浏览结果。
4. 用户不会因为“输入框里还有字”就自动得到一组看不懂来源的过滤结果。

## 非目标

- 不要求新增搜索联想
- 不要求新增搜索历史入口
- 不要求修改商品排序策略

## 补充说明

这个需求的重点是让用户清楚地知道：什么时候自己在“搜”，什么时候自己在“逛”。
